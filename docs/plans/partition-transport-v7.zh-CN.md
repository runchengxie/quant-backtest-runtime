# 分区传输 v7 提案（未启用）

[English](partition-transport-v7.md)

本文保留原有的广泛设计提案。单独定义的[分区会话队列 v7](../queued-sessions.zh-CN.md)
已通过现有引擎会话通道提供有界执行。下文开放的格式仍需分别审阅。
现行 v6 会话请求保持既有内嵌输入与大小限制，`partition_manifest.v1` 引用只能按显式 v7 约定使用。

未来采用新版本协议的引擎消费者可以接收清单摘要及操作者显式批准的输入、任务目录，验证金融负载后，
消费[已验证的分区输入 v1](../partition-inputs-v1.zh-CN.md)。runtime 负责引用校验和有界读取，
金融引擎负责撮合、记账、信息可见性和检查点兼容性。任务控制、预算、取消与发布校验仍须保持权威。

启用前需要单独审查引擎请求版本、任务版本、能力协商、端到端有界输入与结果通道、固定引擎版本的集成测试，
并证明既有格式和指纹不变。通过未校验的子进程参数传递路径，或提高 v6 传输上限，都不满足这些要求。
未来具体的线路格式尚待确定。

检查点适配器必须把金融检查点版本、配置身份与输入游标中的清单摘要及下一行位置原子绑定，完整保留待报告
信息及全部金融状态，拒绝不兼容状态，并验证跨分区、不同批量大小及恢复执行时，事件、成交、费用、现金、
持仓和最终净值均一致。仅证明输入游标正确不能提供这些金融保证。本提案没有实现生产金融引擎检查点或
流式会话传输。
