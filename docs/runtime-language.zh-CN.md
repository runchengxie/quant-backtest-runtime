# Runtime 的语言方向

[English page](runtime-language.md)

Go 已实现 CLI 任务管理、SQLite 状态、单机常驻调度、进程管理和结果发布。Rust 继续作为独立发布的回测引擎。Python 保留现有金融计算与契约，通过可选的兼容适配器接入。目前尚未进行生产切换。

## 当前职责

| 组件 | 负责方 |
| --- | --- |
| 任务领取、租约、取消和恢复 | Go runtime |
| 队列调度与明确的并发上限 | Go runtime |
| 最终产物校验与发布 | Go runtime |
| v5、v6 原生执行 | 独立 Rust 引擎，由 Go 管理进程 |
| 旧版金融计算与规范化 | 可选的无状态 Python 适配器 |
| 策略、研究来源记录和晋升规则 | 研究仓库 |

Go 原生执行 v5、v6 任务时无需 Python。旧版操作使用明确配置的解释器，该环境需要安装 `quant-backtest-runtime[legacy]`。适配器写入暂存产物并返回计算结果，不管理 SQLite，也不发布最终目录。原有 Python CLI 继续保留，供兼容使用和回滚；交给它管理的数据库必须由它独占。

普通 `submit` 立即启动独立 worker。队列调度通过 `submit --queue` 和 `serve --concurrency N` 使用，每个队列数据库只运行一个调度器，两种提交模式不能混用。并发上限覆盖调度器管理的 worker，进程完成回收后才释放名额。命令与部署步骤见 [Go runtime 使用指南](go-runtime.zh-CN.md)。

## 进程与协议边界

runtime 打开程序并核对字节摘要，再通过保留的文件描述符执行。重新执行自身的辅助进程会在调用目标程序前设置 Linux 内存限制。父进程死亡信号、明确的进程组终止、输出上限和进程回收共同管理子进程生命周期。取消与恢复通过 pidfd 和精确的 worker 参数核对身份。这些措施用于受信任的工作负载，不能充当不受信任代码的沙箱。

Go 校验引擎结果和金融证据，不实现订单撮合或组合构造。跨语言样例检查规范化请求字节和 SHA-256 身份，金额保留精确十进制表示。现有请求与结果 schema 仍是兼容契约；样例测试通过并不代表所有历史任务都已兼容。

## 部署状态与待补证据

实现已可使用独立的合成任务数据库验证，生产数据库和定时任务尚未切换。切换前需要停止 Python 新提交并等待 worker 退出，备份状态与产物，记录共同验证的 runtime、引擎和适配器版本，再让 Go 独占任务管理。回滚时也要先停止 Go，确认没有活动 worker，之后才能恢复 Python 管理。

生命周期测试覆盖队列持久化、并发上限、取消、进程清理和发布完整性。交付生产管理权前，还要验证各部署自己的历史样例和故障恢复流程。在这些检查完成前保留 Python 部署。

目前没有受控的 Python 与 Go 性能对照，无法认定更换语言缩短了完整回测时间。后续测量应将调度开销与引擎计算时间分开，并记录峰值内存和取消延迟。多机调度仍需单独设计共享产物存储、分布式任务领取协议，以及阻止过期 worker 发布结果的机制。
