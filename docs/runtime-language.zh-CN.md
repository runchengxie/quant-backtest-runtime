# Runtime 的语言方向

[English page](runtime-language.md)

当前继续维护 Python runtime。等项目开始建设常驻调度器时，优先验证 Go 原型。Rust 回测引擎继续独立发布，通过版本化 JSON 与 runtime 通信。

这份记录是后续实施依据。仓库目前没有 Go 调度器，也没有 Python 与 Go 的性能对照结果。

## 现在已经有什么

`backtest-job submit` 保存任务后直接启动独立 Python worker。worker 领取任务，调用选定后端并发布结果。SQLite 保存状态和租约，取消与恢复代码会核对进程身份。

v5、v6 任务调用单独安装的 Rust 引擎。runtime 核对程序摘要，通过已打开的文件描述符启动程序。超时后会终止并回收子进程，Linux 父进程死亡信号用于处理 worker 意外退出。基础安装需要 Python 解释器，无需第三方 Python 包。旧回测后端通过 `legacy` 可选安装组提供。

当前缺少常驻队列和全局并发上限。每个任务已有内存和运行时间限制，多任务共享机器时的调度与资源预算需要继续开发。提交很多任务可能同时启动很多 worker。换语言本身不会补齐这些功能。

## 为什么后续先验证 Go

Go 可以用 goroutine 组织等待中的任务，用 channel 或信号量限制同时运行的数量。`context` 可以传递取消与超时。维护者需要验证这种实现是否比继续扩展 Python 更容易理解和排查。

Rust 仍适合实现 runtime，尤其适合需要精细控制系统资源的组件。选择 Go 会增加一门维护语言，团队也要承担跨语言协议测试。当前没有证据证明其中一种语言能明显缩短完整回测时间。

| 方案 | 适合的投入 | 要承担的工作 |
| --- | --- | --- |
| 扩展现有 Python | 尽快补充单机调度，沿用现有测试 | 仍需实现队列、并发限制和恢复 |
| Go 调度器原型 | 比较常驻服务的实现和维护成本 | 重新验证进程控制与任务协议 |
| Rust runtime | 团队希望统一系统组件语言 | 同样需要迁移状态管理和恢复测试 |

Go 官方文档说明，`exec.CommandContext` 默认取消动作是对关联进程调用 `Kill`。实现时还要设计后代进程清理，并调用 `Wait` 回收资源。现有程序的文件摘要校验和进程身份检查也要保留。参见 [os/exec 文档](https://pkg.go.dev/os/exec)和 [Go 并发说明](https://go.dev/doc/effective_go#concurrency)。

## 原型先验证什么

第一轮使用独立的合成任务库和结果目录。Go 调度器可以调用现有 Python CLI，任务状态和结果仍由 Python 维护。Go 只负责决定何时提交下一项任务，通过任务 ID 查询完成状态。

`submit` 命令返回时，worker 可能还在运行。并发名额要等任务进入最终状态且相关进程完成清理后才能释放。调度器重启时还要找回已经提交的任务，用幂等键处理提交成功但响应丢失的情况。调用已有 `cancel` 和 `recover` 命令处理取消与过期任务，Go 原型直接写入同一 SQLite 的做法需要另行设计。

这一轮先测正常完成、排队和调度器重启。通过后再增加故障注入，覆盖任务完成与取消同时发生、worker 意外退出，以及结果发布中断。测试只使用任务自己的临时数据库，保留完整日志和程序版本。

| 检查 | 验收依据 |
| --- | --- |
| 并发上限 | 提交超过上限的任务，持续观测实际存活的 worker，不能超过配置值 |
| 重启与幂等 | 在提交响应前后分别终止调度器，恢复后每个任务只保留一份有效结果 |
| 取消与回收 | 确认目标 worker 和引擎都退出，任务状态与实际进程一致 |
| 协议兼容 | 同一组 v1 至 v6 请求沿用已有指纹、错误码和结果校验 |
| 发布与恢复 | 写入中断后，读取方只能拿到完整且校验通过的结果 |
| 运行成本 | 分开记录调度开销与引擎计算时间，同时记录峰值内存和取消延迟 |

现有 Python 实现是第一份对照。记录固定机器、相同输入和同一引擎程序摘要，再比较结果。先确定可接受的资源预算和取消时限，看到数据后决定是否迁移。

## 真正迁移时怎么切换

先固定跨语言兼容样例，覆盖 JSON 规范化、请求 SHA-256 和幂等行为。金融金额继续保留十进制字符串，不能经过二进制浮点数再生成摘要。

Go 接管状态管理前，要明确 SQLite 的唯一管理者，并将 worker 改成只计算、写入暂存产物和返回执行结果。随后由 Go 管理任务领取、租约和最终发布。迁移期间保留旧版本回滚路径，同一任务不能同时交给两套状态管理实现。

单机调度稳定后再评估多机。远程 worker 需要共享产物存储和新的领取协议，还要阻止过期 worker 提交结果。语言选择不会代替这些设计。
